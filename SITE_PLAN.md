# Демонстрационный сайт «Конжак»

Каждая новая задача продолжает опубликованную ветку предыдущей.
1. Исправить работающую ссылку на форму.
2. Общее оформление и маршруты пяти страниц.
3. Домики: описание и выбор заявки.
4. Квадротуры и обзорные точки: иллюстрации, описания.
5. Общая заявка на поход, домик или тур; проверка и сохранение в SQLite.
Это демонстрационные предложения без оплаты и обещания реальной доступности.
tests/test_site_contract.py — независимый защищённый контракт приёмки.

## Итерация 4
Реализовать только новый модуль src/booking.py, без подключения к HTTP (это отдельная следующая задача). submit_booking(db,kind,name,email,start_date,people) сохраняет в SQLite таблицу bookings(kind,name,email,start_date,people), сохраняя прежнюю registrations. kind только hike/cabin/quad. Имя и email обрезаются по краям и проверяются так же, как в src/registration.py (повторно использовать validators при наличии). Дата: точный ISO YYYY-MM-DD, сегодня или позже, иначе ValueError. people только int (не bool и не строка) 1..12. Все неверные данные вызывают ValueError до вставки; SQL параметризованный; соединение закрывается. render_booking(kind,success=False) возвращает компактный HTML фрагмент формы method="post" action="/booking": select name="kind" для трёх услуг, required и подписи для name/email/start_date/people; type email/date/number, min/max. Неизвестный kind безопасно заменяется hike, сырые параметры не вставлять в HTML. Только success=True показывает текст «Заявка принята». Нет оплаты, обещаний доступности, скриптов и внешних ресурсов. Файл не более 4000 символов целиком. Существующие страницы и HTTP не менять.

## Итерация 5
Подключить существующий src.booking к веб-сайту, изменяя только src/site.py и src/server.py. GET /booking показывает render_booking(kind,success), kind из query, неизвестный kind безопасно нормализует booking-модуль. render_route получает необязательный kind третьим аргументом. Общая навигация всех пяти страниц /, /cabins, /quad, /views, /booking. На домиках и квадротурах ссылка на /booking?kind=cabin или quad; походы hike. POST /booking принимает только application/x-www-form-urlencoded и ровно пять одиночных полей kind/name/email/start_date/people. Ограничение тела максимум 4096 байт, иначе 413; неверный Content-Type 415; Origin при наличии обязан соответствовать Host, иначе 403; неверные/дублированные поля/значения 400. Преобразовать people в int перед submit_booking; ValueError даёт 400 без вывода введённых данных. SQLite путь из SQLITE_PATH как у прежней регистрации. Успех 303 на относительный /booking?success=1, затем текст «Заявка принята». Сохранить старый POST /register, все страницы, атрибуции фотографий, белый список трёх JPEG, CSP и 404 чужих путей. Никаких новых библиотек, скриптов, внешних загрузок, оплаты. Полное содержимое двух файлов в сумме не более 4800 символов: переиспользовать готовые render_booking, submit_booking и src.activities._page(title,nav,body), не копировать HTML-шапку и CSS для домиков/формы; ссылку /#register в HTML квадротуров можно заменить на /booking?kind=quad внутри src/site.py. Краткий код без длинных комментариев.
